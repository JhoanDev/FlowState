#### 7. Regras de Backend (Tauri v2 + Rust + SQLite)

* **7.1 Arquitetura Modular Estrita:** É terminantemente proibido concentrar a lógica no arquivo `main.rs`. O código Rust deve ser dividido em módulos semânticos dentro de `src-tauri/src/` (ex: `commands/`, `database/`, `models/`, `state/`). O `main.rs` serve apenas para inicializar plugins e registrar comandos.
* **7.2 Zero Panics (Tratamento de Erros IPC):** Nunca utilize `.unwrap()` ou `.expect()` em funções que se comunicam com o frontend (`#[tauri::command]`). Qualquer falha (ex: erro no banco de dados) deve ser mapeada para um `Result<T, String>` ou um `CustomError` serializável. O aplicativo nativo **não pode fechar (crash)** por erros de execução.
* **7.3 Contratos de Tipagem (Serde e Nomenclatura):** Todas as `structs` do Rust que trafegam via IPC devem implementar `#[derive(Serialize, Deserialize)]`. Para garantir alinhamento perfeito com o TypeScript e o banco de dados, utilize a macro `#[serde(rename_all = "camelCase")]` nas structs que vão para o frontend, mantendo o padrão `snake_case` nativo do Rust e do SQLite internamente.
* **7.4 Segurança Default-Deny (Capabilities v2):** O Tauri v2 bloqueia todas as chamadas IPC por padrão. Todo novo comando Rust criado (`invoke('meu_comando')`) ou acesso ao banco via `tauri-plugin-sql` deve ter sua permissão explicitamente declarada nos arquivos JSON dentro da pasta `src-tauri/capabilities/`.
* **7.5 Consultas SQL Seguras e Migrations:** Todo acesso ao SQLite via `tauri-plugin-sql` (seja por comandos Rust ou diretamenta do frontend, caso habilitado) deve obrigatoriamente usar **queries parametrizadas** (ex: `SELECT * FROM tags WHERE id = $1`). É proibida a concatenação de strings para montar SQL. A criação das tabelas (Schema) deve ser gerenciada pelo sistema de migrations do plugin no momento da inicialização do app.
* **7.6 Gerenciamento de Estado Concorrente:** Dados globais em memória (como configurações de sessão ativas ou timers em background) devem ser gerenciados através do `tauri::State`. Para garantir *Thread Safety*, os estados devem ser encapsulados em `std::sync::Mutex` ou `tokio::sync::Mutex`.
* **7.7 Offloading da UI Thread:** Comandos pesados (como exportação/importação de backup ou geração de relatórios complexos que iteram sobre milhares de logs) devem ser executados de forma assíncrona (`async fn`) para não travar a thread principal da interface do usuário.
